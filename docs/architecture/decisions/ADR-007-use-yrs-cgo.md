# ADR-007: 使用 Yrs (CGo) 作为 CRDT 实现

**日期**: 2026-05-22

**状态**: 已接受

---

## 背景

同步引擎需要 CRDT 实现来支持冲突-free 的多设备数据合并。需要决定使用现有成熟实现还是自研。

## 选项

| 方案 | 优点 | 缺点 |
|------|------|------|
| **Yrs CGo** | Rust 核心高性能、经过生产验证（AFFiNE） | CGo FFI 增加编译复杂度 |
| **自建 Go CRDT** | 纯 Go、无 FFI、编译简单 | 正确性验证极难、开发周期长 |
| **Yjs WASM** | 纯前端成熟、多语言支持 | WASM 在 Go 中调用开销大、生态偏前端 |

## 决策

选择 **Yrs** 通过 CGo FFI 集成。

## 理由

1. **生产验证** — Yrs 被 AFFiNE、Mozilla 等项目使用，RLE 数组实现经过实战检验
2. **性能** — Rust 原生实现的 CRDT 合并性能远优于纯 Go 或 WASM 方案
3. **功能完整** — 支持文本、数组、Map、Xml 等 CRDT 类型，覆盖块级编辑需求
4. **社区活跃** — 持续维护更新，有明确的 API 稳定性保证

## 影响

- 编译时需要 CGo 工具链（Windows 需要 GCC/MinGW）
- 生成构建产物需要额外 CI 配置
- CGo 调用有轻微性能开销，但 CRDT 操作频率较低（每次编辑触发一次），可接受
- 作为备选方案，可评估纯 Go CRDT 库的成熟度
